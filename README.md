# Системи управління бібліотекою

Цей застосунок створено як лабораторну роботу №2. Він дозволяє вести облік книг та користувачів, позичати та повертати книги. 

## Висновок щодо порівняння Webpack та Vite

Під час розробки застосунку була виконана міграція з Webpack на Vite. Нижче наведено порівняльний аналіз цих двох інструментів для невеликих SPA-проєктів:

### 1. Швидкість старту dev-сервера та HMR
- **Webpack**: стартує дещо довше, оскільки збирає та бандлить увесь проєкт в пам'яті перед тим, як віддати його в браузер. HMR працює нормально, але на більших проєктах може уповільнюватись.
- **Vite**: стартує практично миттєво, оскільки використовує нативні ES-модулі браузера. Замість бандлінгу він просто віддає файли на запит, а HMR (Hot Module Replacement) відбувається набагато швидше і зберігає цей темп незалежно від розміру застосунку.

### 2. Час і складність налаштування конфігурації
- **Webpack**: потребує великої кількості конфігурації (налаштування loaders для TS, SCSS, плагінів на кшталт `HtmlWebpackPlugin`). Для правильної роботи Typescript знадобився `ts-loader`.
- **Vite**: працює "з коробки" для TypeScript, CSS, SCSS. Не потребує додаткових лоадерів. Файл конфігурації `vite.config.ts` займає всього декілька рядків.

### 3. Розмір і швидкість продакшн-збірки
- **Webpack**: збірка відбувається довше через глибоку трансформацію модулів. Розмір бандлу оптимізується за допомогою Terser, проте це потребує ресурсів під час білду.
- **Vite**: використовує `Rollup` під капотом для продакшн-збірки. Час збірки менший, а фінальний розмір оптимізований дуже добре. 

### 4. Зручність підключення UI-фреймворку та TS-лоадерів
- **Webpack**: для Bootstrap знадобилися `style-loader`, `css-loader`, `sass-loader`, а для TypeScript - `ts-loader`.
- **Vite**: Bootstrap підключився автоматично через імпорт CSS/SCSS файлів в точці входу. TypeScript компілюється миттєво через `esbuild` без лоадерів.

### 5. Екосистема плагінів
- **Webpack**: величезна кількість плагінів, що формувалась роками, але їх налаштування часто буває крихким.
- **Vite**: екосистема активно розвивається (наприклад, `@vitejs/plugin-vue` чи `@vitejs/plugin-react`). Для базових потреб плагіни часто навіть не потрібні.

### 6. Суб’єктивна оцінка для подібних невеликих SPA-проєктів
Для даного проєкту (невеликий SPA без фреймворків) Vite є абсолютно беззаперечним лідером. Він значно економить час розробника на налаштування, надає фантастичний Developer Experience (DX) завдяки миттєвому оновленню сторінки, і робить код чистішим за рахунок відсутності зайвих файлів конфігурацій та лоадерів. Webpack залишається потужним інструментом для складних Enterprise-застосунків із специфічними вимогами до збірки, але для таких завдань Vite — ідеальний вибір.
